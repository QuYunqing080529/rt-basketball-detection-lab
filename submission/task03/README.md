## 一、评测口径（冻结，后续各题沿用）

| # | 口径项 | 规则 | 实现位置 |
|---|---|---|---|
| 1 | 匹配门槛 | 预测框与人工框 **IoU ≥ 0.50** 才算“找到” | `lab.py` `MATCH_IOU = 0.50`（第 19 行） |
| 2 | 分组规则 | 人工框为空 → `empty`；人工框触碰画面任一边 → `edge`；短边按长边折算到 640 后 **≤ 36 px** → `small`；其余 → `regular` | `lab.py` `group()`（第 137 行） |
| 3 | 统计写法 | **匹配帧数 / 有球帧数**、**误报帧数 / 无球帧数**，分子分母都要写出；有球帧内多余框单独记 `extra_boxes` | `lab.py` `evaluate()` |
| 4 | 固定入口 | `lab.py eval --split val --imgsz <尺寸> --conf <阈值> --output <文件>`；权重 `yolo11n.pt`，设备 `cpu`，类别自动取 `sports ball` | `lab.py` `main()` |

验证集固定为 `annotations.csv` 中 `split=val` 的 **14 帧**（12 有球 + 2 无球；其中 `edge` 2 帧、`empty` 2 帧）。

## 五、取舍结论（第 14 题）

**不采用 320，保持 640；阈值取 0.10。**

| 判断依据 | 数据 |
|---|---|
| 320 保不住边缘球 | 边缘球 A `1/2` → B `0/2`，第 145 帧在 320 下**连 0.10 都过不了**（无检测） |
| 320 还会丢完整球 | 第 225 帧在 640 下 `0.251` 命中，320 下无检测 |
| 320 并非全面变差 | 第 25 帧反而被 320 找回（`0.316`），说明缩小输入不是单调损失细节，也会改变尺度匹配 |
| 有球总数 | A `4/12` → B `3/12`，净少 1 帧，但丢的是最难的两类（边缘球、低分球） |
| 误报代价 | A/B/C 三组无球误报全部 `0/2`，降阈值在这批图上**没有带来误报** |
| 若必须用 320 | 选 `0.10`（`3/12`）而非 `0.25`（`2/12`），但边缘球仍是 `0/2`，达不到“保住边缘球”的目标 |

**保守提醒**：0.10 是低门槛，本批 14 帧无误报不代表其他素材无误报。第 5 题已固定使用 640 + 0.10 做独立测试，正好可以检验这一点。
